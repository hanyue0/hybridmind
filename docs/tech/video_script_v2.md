# HybridMind 演示视频 · 拍摄脚本（v2 · 论文精读版）

> 目标时长 5 分 40 秒，1920×1080，普通话讲解 + 字幕。
> 画面由程序自动录制（CDP 驱动真实页面），**你只需要照着下面的稿子配音**。
> 配音文件放 `D:\桌面\AMC-传智\配音\v2\`，按段命名：`段1.mp3 … 段6.mp3`；
> 也可以录一整个文件（中间自然停顿），我来切分。

## 配音要求

| 项目 | 要求 |

| 格式 | mp3 / wav / m4a 都行，不要做任何降噪或压缩处理 |

## 段 1｜痛点（0:00–0:45，约 175 字）

**画面**：黑底标题卡 → 论文首页局部 → 一句 AI 回答被红框圈出、旁边浮出"44.1 还是 41.4？"

> 读一篇英文论文，最花时间的不是从头看到尾，而是回答一个具体问题：这篇在哪个数据集上评的？报告的那个指标是多少？
>
> 把这些丢给大模型，几秒就有答案，而且说得特别顺。但论文里最要命的就是这种顺——它把四十四点一记成四十一点四，你不翻原文根本看不出来。
>
> 我自己的用法一直是先问 AI、再翻原文核对。可如果每次都要核对，我省下的时间又还回去了一半。
>
> 所以我想做的不是让它答得更像人，而是让它答完之后，我能指着原文说：就是这句话。

## 段 2｜方案与演示（0:45–2:05，约 310 字）

**画面**：`/paper` 界面全屏。选中 RAG 论文 → 输入中文问题 → 答案流式出现 → 点击锚点 S30 → 左侧自动翻到第 4 页并高亮。

> 这是 HybridMind，一个中文论文精读助手。
>
> 上面选一篇论文，我在右边用中文提问：RAG 使用多少篇 Wikipedia 文档？
>
> 注意看左边：它答的是二十一个百万，也就是两千一百万。这个数字不在第一页，是系统自己检索到第四页去的。
>
> 更关键的是下面这条证据锚点：S 三十，第四页。点一下，左边自动翻到第四页，把命中的那几行框出来。
>
> 这条锚点不是模型自己标的。我实测过，一点五 B 的小模型经常不写出处，它把话说圆就完了。所以系统加了一层确定性对齐：用数字、英文术语、还有建库时生成的中文译文，把答案句重新钉回原文。
>
> 模型守不守规矩，都不影响我核对。

## 段 3｜难题升级（2:05–2:55，约 195 字）

**画面**：切到第二个问题（RAG-Token 与 RAG-Sequence 的区别）→ 路由条从"本地"变成"云端"→ 新增锚点 → 再次高亮。

> 再问一个难的：RAG-Token 和 RAG-Sequence 有什么区别？
>
> 这次证据散在好几页，本地答完之后的校验没通过，系统自己升级到云端重答，然后重新校验。
>
> 所以它的路由逻辑不是猜"这道题难不难"，而是先答、再验：答案里有锚点、引用编号真实存在、数字能在原文里找到，就留在本地；有一条不成立，才花钱上云。
>
> 在这台没有独显的笔记本上，本地答一题要十秒左右，云端不到一秒。多等这十秒值不值，取决于本地答案的通过率——实测是百分之六十九。

## 段 4｜数据（2:55–4:10，约 290 字）

**画面**：先出三策略柱状图，再切门控判别力图，最后切成本—质量散点图。

> 我把三篇论文、六十八道中文题跑了一遍，四种设置。
>
> 全本地，准确率六十三点二，证据召回六十四点五——三分之一的回答连出处都给不出。
>
> 全云端，准确率八十六点八，证据召回九十一点九，但每次问答都要花钱。
>
> 然后是学习型路由，也就是我上一版用的"预测本地会不会答错"。它在这个场景里彻底失效了：交叉验证 AUC 只有零点六一，阈值一卡，百分之九十三的请求都要上云，等于没路由。
>
> 最后是证据门控：准确率八十五点三，和全云端只差一道题；证据召回九十三点五，最高；误拒率百分之三点二，最低；云端只用掉百分之三十九点七，每千次成本从一块六毛九降到六毛六，降了六成。
>
> 它没有比云端更准，但它更便宜，而且更能指出处。

## 段 5｜回答质疑（4:10–4:55，约 175 字）

**画面**：左侧长上下文示意（一整页缩成小字、关键段落被压在中部）→ 右侧检索 + 锚点的三行要点。

> 有人会问：为什么不直接把整篇论文塞进上下文？
>
> 三个原因。第一，一篇二十页的论文一万五千 token，每次提问是三毛钱这个量级，比检索方案贵一个数量级。
>
> 第二，已有实验证明，关键信息落在长上下文中部时，模型的表现明显下降——而论文的方法和实验，恰恰在中间。
>
> 第三，也是最重要的：整篇塞进去，模型知道答案，但它给不出一个能画高亮框的坐标。
>
> 检索不只是为了省钱，是为了让答案有位置。

## 段 6｜收尾（4:55–5:40，约 175 字）

**画面**：终端跑测试（48 项全绿）→ git log 滚动 → 文档/图表目录 → 三行结论字卡。

> 工程上，这个系统一条命令起服务，四十八个单元测试全绿，评测集、图表、文档全部由脚本生成，没有一个手填的数字。
>
> 它当然不完美：只有三篇论文、六十八道题，准确率差一道题说明不了太多；表格跨行跨页的时候，检索还是会漏。
>
> 但它至少把一件事说清楚了：让 AI 答论文，重要的不是答得更像，而是答完之后，你能用一秒钟验证它。
