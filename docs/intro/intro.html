一、项目详情及使用方式

1.1 这个项目解决什么问题

把一个 AI 应用装到普通人的电脑上，会立刻撞上一个两难：全用云端大模型，答得准、回得快，但每次调用都要付费、要联网、数据要离开本机；全用本地小模型，零边际成本、数据不出设备、断网可用，却会在稍微复杂的问题上出错。

HybridMind 在用户与大模型之间加了一层路由：每次请求到达时，先预测「本地模型能不能答对这道题」，判得准就留在本地，判不准才升级到云端；本地答完还会自评置信度，仅在不确信时才重答。整个决策连同理由、耗时、费用一起展示给使用者。

1.2 怎么用（在线演示）

打开 https://hanyue0-hybridmind.ms.show，不需要注册、不需要任何配置：

  1. 在左下输入框里提问，回车发送；
  2. 右侧「路由决策」面板实时显示：走到哪一档（本地 / 云端）、预测的本地答对概率、判定阈值、判定理由、延迟、费用、token 数；
  3. 顶部三个按钮可以现场对比：自动路由（默认）、强制本地、强制云端。同一道题用三种模式各问一次，差异一目了然；
  4. 底部状态栏累计：请求数、本地占比、累计花费、升级次数。

建议试这两题：计算 87 + 8 的值。（会走本地，费用 ¥0）与某商品原价 520 元，先涨价 25%，再降价 20%，最终售价是多少？（会走云端，费用约 ¥0.0002）。

1.3 怎么在本地跑起来

git clone https://github.com/hanyue0/hybridmind
cd hybridmind
python -m venv .venv && .venv\Scripts\pip install -r requirements.txt
ollama pull qwen2.5:1.5b
copy .env.example .env          # 填入自己的云端 API 密钥
python -m uvicorn app.web.main:app --port 8000

浏览器打开 http://127.0.0.1:8000 即可。也支持 docker compose up 一键起「Ollama + 应用」，或使用根目录的 Dockerfile 构建单容器镜像（应用与 llama.cpp 推理服务同容器，无需外部守护进程）。

二、项目亮点

2.1 把「题目难不难」换成「本地会不会答错」

多数同类方案用关键词或文本长度判断难度。本文的实测证明这条路走不通：在 40 条全新句式的分布外题目上，规则路由的难度分从均值 0.33 塌到 0.14（特征词表一个都没命中），路由形同虚设，准确率停留在全本地的 75.0%。

改为用本地模型的真实作答结果当标签训练分类器（5 折交叉验证 AUC 0.9355）后，同等云端预算下准确率达到 87.5%–90.0%，领先规则路由 12.5 个百分点，甚至超过全云端方案（87.5%）——因为有些题本地答对而云端答错，路由把它们留在了本地。

2.2 敢报告对自己不利的结果

项目最初的立论是「本地更便宜更快，所以把简单请求留在本地」。实测推翻了它：在同一台机器上，云端准确率高 32.5 个百分点、延迟只有 1/8、千次调用只要 ¥0.19。

文档没有回避这个结论，而是把它写进正文第一章，并据此重构了问题的定义——路由的价值在隐私、离线可用与规模化成本，而不是省下那两毛钱。答辩时这是加分项：作者知道自己的方案边界在哪。

2.3 全链路可复算

评测集由脚本按固定随机种子生成，标准答案由生成过程精确计算；判分不使用大模型当裁判（数值题取最后一个数字并剥离余数从句，短答题做别名匹配），评委可以逐条复算；每一张图、每一张表都有对应脚本，一条命令重跑。

2.4 在无显卡的普通笔记本上跑通全链路

开发与录屏环境为 i5-13420H / 16 GB 单通道内存 / Intel 核显，本地推理纯 CPU 约 3–4 token/s。公网演示部署在 2 vCPU / 8 GB 的免费实例上，单容器同时跑应用与 1.5B 模型。

三、AI 能力的测试与评估落地情况

本项目不仅是「用 AI」，还包含一套针对 AI 输出质量的评测体系，这也是我们把结论说得有底气的依据。

评测要素做法为什么这样做
评测集160 条四难度档封闭答案题 + 40 条分布外题封闭答案才能自动判分，且可被第三方复算
判分数值取末位数字（剥离余数从句）、短答比别名避免"用大模型证明大模型"，无额外费用、可逐条复核
对照全本地 / 全云端 / 规则路由 / 学习型路由 / oracle 上界没有基线就没有说服力
一致性指标准确率、云端占比、千次成本、P50/P95 延迟路由是取舍问题，单指标会误导
泛化检验40 条全新句式，两端均不重训只看训练分布内的数字会得出完全错误的结论
工程回归22 项单元测试（路由、判分口径、置信度解析、回退逻辑）改阈值/改判分规则时防止行为漂移

四、项目中涉及的关键技术

4.1 双后端同构抽象

本地（Ollama / llama.cpp）与云端（OpenAI 兼容）实现同一套 generate() 接口，返回同一种 Generation 结构。正因为同构，路由切换对编排层透明，成本账本才能用同一套代码统计两种后端。

4.2 学习型路由

14 维题面特征（长度、语句数、数字个数、运算符数、是否含百分号、数学/应用题/推理词命中数等）+ 标准化逻辑回归。训练期用 scikit-learn，运行期导出为纯 Python 点积，部署端不需要 sklearn；导出结果与 sklearn 预测的最大偏差经脚本校验为 0.000000。

4.3 分层降级与置信度兜底

任一端推理失败自动切到另一端并在界面说明；本地作答后可自评置信度，仅在「本地答对概率落在不确定区间」时才触发重答——这条规则是被一次真实事故逼出来的：问「1+1」时概率 0.99 却仍被自评拖去云端，白花一次调用。

4.4 单容器部署

托管平台一般只给一个容器。因此生产镜像内同时运行应用与 llama.cpp 的 OpenAI 兼容服务，模型权重在构建期下载、运行期离线，按平台注入的端口监听。
